1. **P2 — Strict hydration can accept malformed data as fresh.** [pipeline/enrichment.py:157](/home/d/code/hn-rerank/pipeline/enrichment.py:157)
   For an HN story with a stored article body and zero stored comments, force refresh and return HTTP 200 with `{"type":"story"}` from Algolia. The type check passes; the preserved article body makes `text_content` nonempty. The function then writes empty/default title, URL and score fields and returns a `Story`, which the server treats as verified hydration and sends to generation. Expected: reject malformed or mismatched items before writing, preserve the existing row/cache, and return a retryable failure or stale fallback without an LLM call. `strict=True` needs boundary validation beyond the item’s type.

2. **P2 — Repeated `r` leaves a permanent forced-intent guard.** [app.py:1502](/home/d/code/hn-rerank/clients/tui/src/hn_rerank/app.py:1502)
   Start a forced summary request and hold it. After its first stats check finishes, press `r` again; let the second stats check observe 25 comments against snapshot 10. The second load reuses the active forced task, returning before `_forced_intent.pop()` executes. When generation completes with snapshot 10, the deferred growth check encounters the latest intent and defers again, although no generation remains. Further stats checks at that selection keep deferring. Expected: one paid request, followed by a growth choice when its returned snapshot remains behind. Consume the new intent when joining an existing forced task, or clear it when that load completes.

3. **P2 — A sort-refresh reply can overwrite an acknowledged vote’s pending version.** [app.py:1737](/home/d/code/hn-rerank/clients/tui/src/hn_rerank/app.py:1737)
   Hold a sort-triggered feed GET whose payload is version V, `ready=True`. While it waits, complete a vote/undo POST returning target V+1; `submit()` correctly marks the current feed pending. Release the older GET. API identity and feed serial still match, so `set_feed()` replaces the acknowledged target with V and `ready=True`; the following branch also clears optimistic `restored` rows. Expected: preserve the pending target and undo state until a feed covers that target. The new reply guard tracks feed requests, but not intervening vote acknowledgements.

4. **P2 — Stats and decline state survive profile replacement.** [app.py:1059](/home/d/code/hn-rerank/clients/tui/src/hn_rerank/app.py:1059)
   Decline growth at 25 comments under profile A, then connect profile B with the same story and a known older snapshot. `connected()` resets summaries but leaves `_stats_offered`; B’s observation of 25 is suppressed by A’s decline. Likewise, a held A stats request remains in `_stats_requests`, causing B’s check for that story to return early; A’s eventual reply is discarded without performing B’s check. Expected: cancellation/reset of profile-scoped stats state, or keys that include API/profile identity.

5. **P3 — Joining warm generation loses a known snapshot.** [server.py:1713](/home/d/code/hn-rerank/server.py:1713)
   Let warm prefetch lead generation, then join it through an ordinary TLDR request. Prefetch stores `source_comments` with the text, but publishes `_tldr_result_reply()` without snapshot metadata. The joining TUI stores the complete text with an unknown baseline, preventing growth prompts even though the corresponding cache record has a known baseline. Expected: include the captured snapshot in successful, complete warm-flight replies. The existing prefetch/join regression explicitly expects the metadata-free payload.

6. **P3 — Popup copy overstates discussion coverage.** [app.py:645](/home/d/code/hn-rerank/clients/tui/src/hn_rerank/app.py:645)

Expected wording should express the snapshot, for example: “Discussion had 500 comments when summarized; 550 now.”
