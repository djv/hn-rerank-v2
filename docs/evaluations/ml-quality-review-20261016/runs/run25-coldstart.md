# Cold-start, new profiles, freshness review

## 1. Top findings / proposals (ranked by value per effort)

**1. Tier-1 gravity is zero for all score-0 sources — new users get HN-only Recommended.** Category: defect. Evidence: `pipeline/ranking.py:1769-1779` — `tier1 = score/(age_h+2)^1.8`; RSS/Reddit rows have `score≈0`, so all tie at 0 and order is input-order; `pipeline/__init__.py:376` RSS leg is `ORDER BY time DESC` but ranking ignores it. Cold/1–20-vote decks (`ranking.py:1783,1807-1811`, `alpha_2=n/50`) are ~all tier-1. Effect: save-time OK for HN, but discovery/currentness fail for non-HN; sameness rises (HN frontpage clone). Effort: S. Fix: per-source tier-1 prior (e.g. RSS tier-1 = recency percentile, or small learned source intercept active only when `alpha_2<1`). Validate: `eval_ranker_variants.py --train-recent 0/20/50` + cold-deck source-mix report (`deck_composition_report.py`); metrics: NDCG@12 + non-HN share + novel-up rate. Confidence: high that defect exists, medium on best prior.

**2. Cold deck has no Explore and no far card.** Category: defect. Evidence: `pipeline/__init__.py:169-223` calls `assemble_window_deck` with no `explore`; `ranking.py:2120-2135,2388-2405` far card needs `closest_up<0.60`, which is `None` without Explore. So a new profile's first feed is gravity Recommended + gravity Popular only — the two most same-y views. Effect: worst on discovery/sameness; calmer habit neutral; currentness neutral. Effort: M. Fix: cold-Explore surrogate (recency + source round-robin + MMR-0.8 over gravity order, 3/slot) for `n_up<20` or `explore is None`. Validate: Diversity Phase-0 replay (`docs/evaluations/diversity-20261012/PLAN.md`) on cold decks; gate: diversity +0.05 with up-diff ≥−2pts. Confidence: medium-high.

**3. Dual gate + 20/80 ramp strands users in tiers 1–2 for months; tier-2 centroid is weak.** Category: untried improvement. Evidence: gate `ranking.py:1310-1311` (`min_up/down=20`), ramp `ranking.py:1790-1800` (`alpha_3=(n_min-20)/60`, full at 80/80); `ARCHITECTURE.md:199-200` documents only the `n_min` formula and omits that `alpha_2=n_feedback/50` uses total votes — doc stale. Short-history curve (`INTERLEAVING.md: Short-history curve`): at N=100 all arms tie (.6926/.6933/.6929); #2 beats prod only at N≥400. Tier-2 (`ranking.py:1746-1763`) is an unnormalized mean-centroid diff, no shrinkage, neutrals ignored. Effect: faster useful personalization helps all four aims; risk is overfitting → same-y if ramp is just lowered. Prefer a *better* tier-2 (kNN-mean + shrinkage, or k=10 mean/max features with logistic, neutrals as half-down) over just lowering the gate. Effort: M. Validate: existing `--train-recent 100/200/400/800/1600` curve (`eval_ranker_variants.py:2470,2257`), metrics AUC + top-12 ups/downs + topic entropy; require block-CI excluding zero before changing defaults. Confidence: medium.

**4. Recommended has no age/velocity/importance term — staying-current rests on windows alone.** Category: evaluation gap + untried improvement. Evidence: feature vector `ranking.py`/`ARCHITECTURE.md:3.2` deliberately excludes score/comments/velocity; Recommended is top-by-model-score per window (`ranking.py:2296`); `check_import_ai_recommended.py` demands a fresh unseen issue in first 8 Recommended on taste alone. Velocity exists only for Hot badge (`ranking.py:2196-2210`) and hot-refresh counts (ARCH 3.7), not ranking. Effect: important-but-dissimilar stories miss; a small freshness prior helps stay-current/save-time but can narrow to hype if over-weighted — keep it tier-1/2-only or as a guaranteed fresh slot, never a global boost. Effort: M/L. Validate: time-split eval with freshness metric (share of held-out ups <48h old in top-12) + Import-AI replay on snapshot; guard with sameness/novel-up metrics from Diversity Phase 0. Confidence: low-medium (untried; prior engagement-feature exclusion in ARCH 3.2 counsels a narrow, gated test, not a full metadata return).

**5. Side-embedding 0.98 global gate penalises fresh stories.** Category: defect. Evidence: `pipeline/side_embeddings.py:170-184` — coverage over candidates+feedback; below 0.98 the *whole* rerank falls back to stored-only, and missing stories get a zero side-half. Fresh stories arriving between 30-min timer ticks (`embed_side_vectors.py`) are the ones missing. Effect: currentness dips exactly when news breaks; sameness neutral. Effort: S. Fix: per-story fallback (score missing rows stored-only) and/or prioritise <6h stories in the timer. Validate: `rank_perf`/`side_embeddings_low_coverage` log rate vs story age + `--replay-embeddings` eval split by age. Confidence: medium.

**6. Fresh low-score HN never enters the pool.** Category: defect/evaluation gap. Evidence: `pipeline/__init__.py:857,883-884` CH `min_score=5`; HN leg `__init__.py:330-337` gravity-ordered cap 10k. A 1h-old story with 2 points loses to a 20d-old 200-pointer before ranking ever sees it. Effect: stay-current hole in 12h/1d windows. Effort: S. Fix: small fresh quota (e.g. always include HN <6h old, cap few hundred) alongside gravity order. Validate: `pool_hn`/`pool_rss_oldest_age_h` trace + missed-upvote age split (`docs/evaluations/missed-upvotes-20261009/REPORT.md` method). Confidence: medium; uncertain how often CH `score<5` rows are noise.

**7. Zero-vote sort inconsistency.** Category: defect. Evidence: `pipeline/ranking.py:~1860` (`n_feedback==0` returns sorted by raw `story.score`) vs `pipeline/__init__.py:157-163` cold deck sorts by `hn_gravity`. `fast_rerank_for_user:1037-1041` masks it live, but direct `_score_and_rank` callers/evals get a different "cold" order. Effort: S (one-line align + test). Validate: unit test cold-equivalence. Confidence: high.

## 3. Open questions

- Is a population prior allowed? E.g. seed a new profile with profile-151's source weights or centroid (shrunk) until N votes — cheap, but is cross-profile leakage acceptable?
- What is "important regardless of taste": velocity, comment growth, cross-source duplication, or an explicit fresh-slot SLA (e.g. one <24h card per window)?
- Should first-feed onboarding ask 5–10 quick votes (active learning) given Teach Phase-0 showed little gain over random (`FINDINGS.md:805`)?
- What `deck_scores` slice defines new-profile success — first-session up-rate, 7-day retention, or novel-up count?
